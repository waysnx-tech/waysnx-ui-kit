# ADR 0001 — UI Kit capability catalog: seed source and intentional partiality

**Status:** Accepted (revised for catalog v0.1.1)
**Date:** 2026-09
**Applies to:** `@waysnx/ui-kit-coverage` v0.1 (Milestone 4 — Replacement Candidates)

## Context

The Replacement Candidate engine (spec §12) needs a catalog of UI Kit components
and their native/semantic alternatives. Constraints (spec §13 + team direction):

- The catalog **may** be supplied/validated from WDG material, **but the
  analyzer must not require WDG at runtime.**
- WDG output must **not** be regenerated by the analyzer for this purpose.

## Decision

The catalog is a committed, versioned, **hand-authored and intentionally
partial** JSON file at:

```
tools/ui-kit-coverage/catalog/ui-kit-catalog.json
```

### Revised catalog — v0.1.1 (current)

Per team approval, the previous v0.1.0 seed was replaced with the revised
**v0.1.1** catalog (`ui-kit-catalog-m4-revised.json`, committed verbatim). Key
properties:

- **15 components** (adds `Image`, `Textarea`; component identity/capability
  facts validated against the supplied WaysNX UI Kit **WDG/AI documentation
  export** — `source.sourceMaterial.runtimeDependency: false`).
- Replacement mappings remain **hand-authored and conservative**
  (`catalogPolicy.replacementMappingsAreHandAuthored: true`).
- Adds a `catalogPolicy` block and per-component `semanticCategory`,
  `catalogEvidence`, and optional `catalogNotes`. The analyzer reads the fields
  it needs and tolerates the additional metadata.

### `table` → data-grid mapping — intentionally absent

- The previous `DataGrid` entry and the `table → @waysnx/ui-data/DataGrid`
  mapping have been **removed** and are **not** recreated.
- The catalog now documents the real component: **`Grid` in
  `@waysnx/ui-grid-builder`**, with `replacement.supported: false` and
  `nativeAlternatives: []`, plus `catalogNotes` stating no `<table>` mapping is
  asserted.
- Therefore **no `table → Grid` (or `DataGrid`) candidate is produced.** A
  `table → Grid` mapping may be added **only in a future catalog revision after
  explicit engineering validation** — not before.

### Rules honored (unchanged)

- **No WDG at runtime**, no WDG regeneration by the analyzer. WDG/AI material was
  used off-line to validate component facts; the analyzer reads only the
  committed JSON (`catalogPolicy.wdgRuntimeDependency: false`).
- **Facts / catalog facts / inferences** kept separate.
- **Incomplete ≠ proof of absence** — a component or mapping missing from the
  catalog never asserts "no UI Kit equivalent exists"
  (`catalogPolicy.missingMappingDoesNotMeanNoEquivalent: true`).
- **Native elements are not automatically replaceable**
  (`catalogPolicy.nativeElementsAreNotAutomaticallyReplaceable: true`); a
  candidate is produced only where the catalog lists a `nativeAlternative`.
- **Expandable without architecture change** — adding/correcting entries is a
  data-only edit.

## Notes

- Previously-flagged package gaps are now **resolved in the catalog**: `Modal`
  and `Tooltip` are under `@waysnx/ui-feedback`, and `Tabs` under
  `@waysnx/ui-layout`.
- `uiKit.repository` (`waysnx-tech/waysnx-ui-kit`) is **transfer-dependent** and
  is left as supplied (data, not a hard-coded source URL).
- `wdgWillBeUsedLaterForCatalogGenerationOrValidation: true` records the intent
  to use WDG for future catalog generation/validation — still with **no runtime
  dependency** in the analyzer.

## Consequences

- Replacement candidates are produced only where the catalog supports a mapping;
  the absence of a `table` mapping is deliberate and enforced by tests.
- Correcting/expanding the catalog (including any future `table → Grid` mapping)
  is a data-only follow-up requiring engineering validation; no analyzer code
  change is required.
